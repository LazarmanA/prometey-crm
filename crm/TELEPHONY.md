# Телефония Прометея — открытый входящий шлюз

Реализован общий серверный API, а не готовые нативные коннекторы операторов.
Профили mango, beeline, mts, t2 — отдельные точки приёма нормализованных событий.
Можно добавить любой идентификатор АТС. Нужен ваш промежуточный адаптер: он
проверяет подпись оператора, сопоставляет его поля и отправляет итог звонка сюда.
Адаптеры Mango/Билайн/МТС/T2, исходящий click-to-call, SIP/WebRTC, всплывающие
карточки во время звонка и автоматическая запись линии в этой версии отсутствуют.
Без конфигурации все входящие шлюзы отключены. В HTML-демо API недоступен.

## Настройка

Node.js 24+, серверная сборка. В окружении процесса задайте TELEPHONY_GATEWAYS:
JSON-объект, например {"mango":"<случайный ключ не короче 32 символов>"}.
Для других подключений добавьте beeline, mts, t2, custom либо своё имя
(латинская буква, затем до 39 латинских букв, цифр, подчёркиваний или дефисов).
Каждому адаптеру выдавайте отдельный секрет. Генерация: node -e
"console.log(require('node:crypto').randomBytes(32).toString('hex'))".
Не кладите ключи в исходники/HTML, не передавайте через URL. Перезапуск применяет
изменения ключей. Для отключения удалите ключ и перезапустите сервер.
Публикуйте только за HTTPS reverse proxy с ограничением частоты и размера запросов.
Текущая сборка сохраняет демонстрационную авторизацию CRM; перед промышленной
эксплуатацией необходимы полноценная авторизация, защита периметра и аудит безопасности.

## Итог звонка

POST /api/telephony/webhooks/mango
Authorization: Bearer <ключ шлюза mango>
Content-Type: application/json

```json
{
  "externalId": "pbx-call-123",
  "phone": "+79001112233",
  "at": "2026-10-15T09:00:00+03:00",
  "direction": "incoming",
  "status": "completed",
  "duration": 62,
  "note": "Обсудили аренду экскаватора"
}
```

externalId уникален в пределах профиля, до 160 символов. Время с часовым поясом;
direction: incoming/outgoing; status: completed/missed; duration: целые секунды
0–86400. Передавайте окончательный итог, а не последовательность состояний.
Повтор идентичного события возвращает duplicate:true без нового звонка.
Изменённое событие с тем же externalId — 409; исправления в CRM вручную.
Идемпотентность сохраняется после перезапуска. Ключи шлюзов не заменяют проверку
подписей оператора: эту проверку обязан выполнять внешний адаптер.

Единственное совпадение телефона с активной компанией создаёт звонок в её карточке.
8XXXXXXXXXX нормализуется в 7XXXXXXXXXX. При неоднозначном или неизвестном номере
событие остаётся без привязки. Руководитель выбирает карточку в «Интеграции →
Телефония». Для явной привязки адаптер может передать target:
{"kind":"orders","id":"o1"} либо {"kind":"clients","id":"c1"}.
Это доверенный интеграционный ключ с доступом к активным карточкам, не ключ менеджера.
Один звонок привязывается к одной карточке; перемещение/удаление не реализовано.
Ответ: {ok, duplicate, event}; event.id нужен для аудиозаписи, event.target — ссылка
на карточку/звонок. Не добавляйте запись, пока target=null; повтор POST после ручной
привязки вернёт уже привязанный event. Максимум 50 000 событий и 1 000 звонков
на карточку; переполнение возвращает явную ошибку, без удаления истории.

## Аудиозапись

PUT /api/telephony/webhooks/mango/<event.id>/recording
Authorization: Bearer <тот же ключ>
Content-Type: application/octet-stream

Тело — байты MP3/WAV, до 20 МБ. Адаптер скачивает запись у своего оператора
и передаёт файл; Прометей не запрашивает произвольные внешние URL.
Повтор того же файла идемпотентен; другая запись вместо существующей — 409.
Запись другого профиля недоступна. Архивная карточка не принимает новые записи.
Прослушивание через CRM доступно только сотрудникам с доступом к карточке.
Файлы хранятся в RECORDINGS_DIR или рядом с SQLite в recordings, вне public.
SQLite содержит метаданные. Резервируйте БД вместе с файлами записей, вместе с полным backup (`npm run backup`).
Настройте правила уведомления собеседников, доступа, сроков хранения и удаления
до включения записи в АТС. Автоматическое удаление по сроку пока не реализовано.

## Подключение операторов

- Mango Office: https://docs.mango-office.ru/ru/5_api-i-razrabotka/1_api-mango-office/1_oglavlenie/index.html
- Билайн, облачная АТС: https://moskva.beeline.ru/business/telephony/cloud-ats/
- МТС, ВАТС Exolve: https://wiki.vpbx.exolve.mts.ru/rest_api
- T2: https://ats2-wiki.tele2.ru/open_api/

Нужно уточнить продукт/тариф АТС, включить API и записи, сопоставить сотрудников,
реализовать и проверить адаптер по документации конкретного аккаунта. Мобильная
SIM-карта сама по себе не предоставляет шлюзу события и записи. Наличие профиля
в интерфейсе не означает подтверждённую совместимость или подключённый аккаунт.
Проверки сборки используют локальные HTTP-запросы; живые АТС не подключались.
